핵심 데이터 흐름

시간 단위 사용량 집계 업로드

1로컬 watcher가 ~/.claude/**/*.jsonl 등 파싱 → SQLite에 분 단위 raw 적재
2옵트인 사용자에 한해 1시간 주기로 시간 단위로 집계 (분 단위는 로컬에만 유지)
3AppSync mutation upsertHourlyUsage 호출 (Slack OIDC 토큰 첨부)
4resolver(JS/VTL)가 $ctx.identity.claims.sub 검증 후 Aurora에 직접 upsert
5리더보드는 query getTopUsers → resolver가 집계 SQL 실행 (Lambda 없음)

채팅 (실시간)

1앱이 subscription onMessage(teamId) 구독 → AppSync가 WSS 연결 유지
2전송 시 mutation sendMessage 호출
3resolver가 권한 확인(team_members) 후 메시지 저장
4AppSync가 같은 팀 구독자 전원에게 자동 push
5연결 유지·fan-out은 전부 AppSync 담당 → 상시 서버 불필요

권한 모델 — DB 테이블 + resolver 집행 (RLS 대체)

테이블주요 컬럼역할
teamsid, name, created_at팀 정의
team_membersteam_id, user_id, role멤버십 — role: owner / member
app_rolesuser_id, role전역 역할 — admin / user
hourly_usageuser_id, hour, tool, model, tokens, cost_usd시간 단위 집계 (UNIQUE 키로 dedup)
messagesid, team_id, user_id, body, created_at채팅 메시지

권한 데이터는 위 테이블에 저장하고, 권한 집행은 AppSync resolver(JS/VTL)에서 수행: Slack OIDC sub → team_members/app_roles 조회 → 허용된 행만 반환. 클라이언트가 DB에 직접 붙지 않으므로(앱→AppSync→Data API→DB) RLS 없이도 안전하고, DB는 인터넷에 노출되지 않습니다.
